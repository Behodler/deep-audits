## Finding description and impact

### Summary

Story-052 (`4788ed4`) added a route-contiguity validator to `CurveAMMAdapter.setRoute`. The validator rejects the "gapped route" shape behind sya-harvester M-01: Curve Router NG stops at the first empty pool slot and delivers whatever intermediate token sits there. At HEAD the validator is Halmos-proven for properties S1–S4.

The live USDe market strategy does not run that code. `ERC4626MarketYieldStrategy.ammAdapter` is `immutable` and points at the non-proxy adapter `0x2D02…D6f`, which was deployed before story-052. It behaves as the `cdd0743` validator (PoC test 1, `test_L30_liveAcceptsGappedRoute_headRejects`), which only checks that the *last non-zero* path entry equals `tokenOut`. Any future owner `setRoute` on `0x2D02` therefore still accepts a gapped route.

If such a route is stored for USDe→sUSDe, every later deposit succeeds and emits a normal `Deposited` event, but the strategy receives crvUSD instead of sUSDe. Two things let this pass. The deposit's `minOut` is denominated in sUSDe *shares*, so roughly 1:1 crvUSD clears it. And the strategy trusts the router's return value as `sharesReceived` without measuring its sUSDe balance. The strategy has no way to move the crvUSD out, so the loss is permanent and is shared across every client of the commingled position.

**This is not live today.** `0x2D02` has emitted exactly two `RouteSet` events (blocks 25283690 and 25283691), and both routes are contiguous and pass every HEAD check. The precondition is a future owner `setRoute`. The finding is filed as a Law-3 owner footgun, not as an attacker path (see "Why this is a footgun, not trusted-owner misuse").

### Vulnerability details

#### 1. HEAD validator (source) vs. deployed validator (bytecode)

The source at HEAD rejects any entry after the executed prefix ([CurveAMMAdapter.sol#L107-L121 @ 4788ed4](https://github.com/Behodler/reflax-yield-vault/blob/4788ed41747b923165745af748a078bfb534ba20/src/AMMAdapters/CurveAMMAdapter.sol#L107-L121)):

```solidity
// Router NG executes hop k while path[2k+1] != 0 and delivers path[2k] at the first empty pool slot.
uint256 k;
while (k < 5 && path[2 * k + 1] != address(0)) k++;
// A zero-hop route is a no-op that would hand tokenIn straight back; never store one.
if (k == 0) revert InvalidRouteEmpty();
// Nothing may follow the executed prefix: a trailing entry is never executed (empty when k == 5).
for (uint256 i = 2 * k + 1; i < 11; i++) {
    if (path[i] != address(0)) revert InvalidRouteGap(i);
}
// Every executed intermediate token must exist: hop i-1 outputs path[2i].
for (uint256 i = 1; i < k; i++) {
    if (path[2 * i] == address(0)) revert InvalidRouteToken(2 * i);
}
address delivered = path[2 * k];
if (delivered != tokenOut) revert InvalidRouteEnd(tokenOut, delivered);
```

The adapter deployed at `0x2D02…D6f` runs the `cdd0743` validator ([CurveAMMAdapter.sol#L73-L80 @ cdd0743](https://github.com/Behodler/reflax-yield-vault/blob/cdd07434a62ae4e1b158eef97dbfef3f2f47d6d9/src/AMMAdapters/CurveAMMAdapter.sol#L73-L80)). It checks only the last non-zero entry:

```solidity
// Find the last non-zero entry in path and confirm it equals tokenOut
address lastToken;
for (uint256 i = 0; i < 11; i++) {
    if (path[i] != address(0)) {
        lastToken = path[i];
    }
}
require(lastToken == tokenOut, "CurveAMMAdapter: path must end at tokenOut");
```

Take the dropped-pool-slot payload `path = [USDe, P1, crvUSD, 0, sUSDe, 0, …]`. The router executes one hop (`k = 1`, since `path[3] == 0`) and delivers `path[2] = crvUSD`. HEAD rejects the payload with `InvalidRouteGap(4)`. The legacy validator sees `lastToken == sUSDe == tokenOut` and stores it.

Because the strategy's adapter reference is immutable ([ERC4626MarketYieldStrategy.sol#L34 @ 4788ed4](https://github.com/Behodler/reflax-yield-vault/blob/4788ed41747b923165745af748a078bfb534ba20/src/concreteYieldStrategies/ERC4626MarketYieldStrategy.sol#L34)), redeploying only the adapter does not reach the live strategy:

```solidity
IAMMAdapter public immutable ammAdapter;
```

#### 2. Adapter swap passes the router's return value straight through

[CurveAMMAdapter.sol#L191-L192 @ 4788ed4](https://github.com/Behodler/reflax-yield-vault/blob/4788ed41747b923165745af748a078bfb534ba20/src/AMMAdapters/CurveAMMAdapter.sol#L191-L192). The legacy adapter has the same shape.

```solidity
// Execute swap; router sends output directly back to caller (receiver = msg.sender)
amountOut = router.exchange(r.path, r.swapParams, amountIn, minAmountOut, r.pools, msg.sender);
```

With a gapped route, Router NG transfers crvUSD to the strategy and returns the crvUSD amount. The adapter never checks which token was delivered.

#### 3. The strategy's deposit floor is in shares and the return value is trusted

[ERC4626MarketYieldStrategy.sol#L135-L146 @ 4788ed4](https://github.com/Behodler/reflax-yield-vault/blob/4788ed41747b923165745af748a078bfb534ba20/src/concreteYieldStrategies/ERC4626MarketYieldStrategy.sol#L135-L146):

```solidity
creditedPrincipal = _creditedPrincipal(amount);

// Minimum acceptable swap output derived from the SAME haircut value, so the credit and the
// swap floor cannot drift apart (provable solvency invariant).
uint256 minOut = vault.convertToShares(creditedPrincipal);

// Approve AMM adapter to spend underlying tokens
underlyingToken.safeIncreaseAllowance(address(ammAdapter), amount);

// Swap underlying -> vault tokens via AMM
sharesReceived = ammAdapter.swap(address(underlyingToken), address(vault), amount, minOut);
require(sharesReceived > 0, "ERC4626MarketYieldStrategy: no shares received");
```

`minOut` is expressed in sUSDe shares. On the fork it is 794.28 for a 1000 USDe deposit, because sUSDe trades at about 0.8 shares per USDe. A 1000 USDe → crvUSD hop returns about 1001 units of an 18-decimal token, which clears the floor easily at the live slippage setting (B = 30). No zero floor or misconfigured slippage is needed. The base contract then books the principal unconditionally ([AYieldStrategy.sol#L708-L715 @ 4788ed4](https://github.com/Behodler/reflax-yield-vault/blob/4788ed41747b923165745af748a078bfb534ba20/src/AYieldStrategy.sol#L708-L715)):

```solidity
(creditedPrincipal, sharesReceived) = _acquireShares(amount, depositor);

// Principal accounting — the single place deposit principal is booked.
clientBalances[token][recipient] += creditedPrincipal;
totalDeposited[token] += creditedPrincipal;

// ...
emit Deposited(token, depositor, recipient, amount, sharesReceived);
```

At no point does the strategy measure `vault.balanceOf(address(this))` around the swap. The crvUSD amount is recorded as `sharesReceived`, so the emitted event looks plausible.

#### 4. No exit path for the stranded token

Every selector on the live strategy was enumerated. None is a sweep or rescue function (`sweep`, `rescueTokens`, `rescueERC20`, `recoverERC20`, `rescue`). `_emergencyWithdraw` moves only vault shares ([ERC4626MarketYieldStrategy.sol#L191-L200 @ 4788ed4](https://github.com/Behodler/reflax-yield-vault/blob/4788ed41747b923165745af748a078bfb534ba20/src/concreteYieldStrategies/ERC4626MarketYieldStrategy.sol#L191-L200)):

```solidity
uint256 totalShares = vault.balanceOf(address(this));
...
IERC20(address(vault)).safeTransfer(owner(), sharesToTransfer);
```

The submitted PoC's `test_L30_strandedCrvUSDHasNoExitPath` shows the crvUSD stays in the strategy. The narrower claims that `skimSurplus`, `totalWithdrawal` and `depositAsOwner` cannot move crvUSD come from a supporting probe outside the submitted patch, `work/test/scan-run18/L30ValidatorProbe.t.sol` (4/4 PASS: `test_probe_skimSurplusCrvUSD`, `test_probe_totalWithdrawalCrvUSD`, `test_probe_depositAsOwnerCrvUSDReverts`, `test_probe_notProxy`; log in `reports/18/poc/L-30-validate.txt`). Overwriting the route stops further losses but cannot recover crvUSD that is already stranded.

#### Why this is a footgun, not trusted-owner misuse (Law 3)

The owner is trusted, and no malicious-owner scenario is claimed here. The test is whether a competent, non-malicious owner would be surprised by the consequence:

- After story-052, the source reads as if `setRoute` rejects gapped routes. An owner (or the phStaging2 scripts where `setRoute` calls originate) who checks a payload against HEAD source or HEAD unit tests will conclude it is safe. The mainnet contract behaves differently.
- `src/CLAUDE.md:258` warns that "the live mainnet adapter `0x2D02…D6f` predates this check, so check any owner `setRoute` there off-chain against these rules." That makes the mistake less likely. It does not say that a mistake on the deposit direction fails *silently and permanently*. An owner who mis-authors a route expects a loud revert, which is what HEAD does and what the withdraw direction does here. They do not expect deposits to keep succeeding while each one is lost.

That surprise is why the finding is reported. The warning lowers likelihood, which is reflected in the borderline rating.

The control test, with the live contiguous route, acquires 796.46 sUSDe for the same deposit (position value +999.75), which shows the loss comes from the route shape alone.

- **Deposit direction (USDe→sUSDe): silent, permanent loss.** Each USDe deposit made while the gapped route is stored is converted to crvUSD that the strategy can never move. The loss is shared across the commingled position. V2 is booked about 490.86 above its backing and co-clients lose about 506.14 per 1000 USDe deposited. V2 emits Antimatter/phUSD, so the shortfall reaches V2 stakers as under-backed principal and dilution. The created `V < D` state also makes V2's `_isUnderwater` check true ([StableStakerV2.sol#L1284-L1286 @ cf8de27](https://github.com/Behodler/stable-staker/blob/cf8de2718816a1c7df794dafb9d567e5694d826d/src/StableStakerV2.sol#L1284-L1286)). While it holds, the guard blocks voluntary withdraw unless V2's on-contract buffer covers it ([StableStakerV2.sol#L1315-L1323 @ cf8de27](https://github.com/Behodler/stable-staker/blob/cf8de2718816a1c7df794dafb9d567e5694d826d/src/StableStakerV2.sol#L1315-L1323)). The PoC proves the under-backed precondition (`assertLt(af.tb, af.prin)`, V2 `totalBalanceOf` < `principalOf`); it does not exercise V2's withdraw behaviour. It also satisfies the precondition of L-32 (and L-28) through an owner action rather than an external NAV decline.
- **Withdraw direction (sUSDe→USDe): revert, availability only.** With a gapped reverse route (`[sUSDe, P2, crvUSD, 0, USDe, …]`), withdraw reverts with `ERC20: transfer amount exceeds balance` on the forward transfer to the client. It reverts only because the strategy holds 0 idle USDe. Withdrawals are unavailable until the route is overwritten.
- **Current exposure: none.** Only two `RouteSet` events exist on `0x2D02`, and both are contiguous.

### Severity rationale

Impact is High (permanent, silent loss of user deposits with no recovery path). Likelihood is Low (it needs a future owner configuration action that has not been taken and that `src/CLAUDE.md` warns about). That gives **Medium**, the same rating as sya-harvester M-01 (same strand class). The poc-validator agreed with every fact above but rated the finding Low because the precondition is a pending owner action. The orchestrator kept Medium under Law 1 (recall beats tidiness) and for cross-project consistency, and flagged it for human triage (`reports/18/decision-log.md` §1). **The owner may downgrade it to Low.** If kept Low, the corrected impact (permanent, silent strand) should still be recorded.

Escalation trigger: re-weigh toward High if any `RouteSet` beyond the two known events appears on `0x2D02` with a payload that fails S1–S4 while deposits are live, because the strand is then realised rather than hypothetical.

## Recommended mitigation steps

**(a) Redeploy with the HEAD (story-052) validator.** `ammAdapter` is immutable on the strategy (`ERC4626MarketYieldStrategy.sol:34`), so deploying a new adapter alone does not protect YieldStrategyUSDe `0xaC2e…7f95`. Redeploy the strategy bound to a new HEAD adapter, or migrate clients to a new strategy that uses it.

**(b) Until then, treat every `setRoute` on `0x2D02…D6f` as unvalidated by the contract.** Dry-run each mainnet payload on a fork against the HEAD `CurveAMMAdapter.setRoute`, or check it off-chain against S1–S4 (no entry after the executed prefix, no zero intermediate, `path[2k] == tokenOut`, valid swap_type on executed rows, zero unexecuted rows and pools). Add this as a mandatory step to the phStaging2 runbook, where `setRoute` calls originate. Extend the `src/CLAUDE.md:258` note to say that a gapped *deposit* route fails silently and permanently, not with a revert.

**(c) Defence in depth: measure what was actually received.** Use the strategy's sUSDe balance delta as `sharesReceived` instead of the router's return value. This turns any mis-delivering route, whatever its root cause, into a loud revert:

```solidity
// ERC4626MarketYieldStrategy._acquireShares
uint256 minOut = vault.convertToShares(creditedPrincipal);
underlyingToken.safeIncreaseAllowance(address(ammAdapter), amount);

uint256 sharesBefore = vault.balanceOf(address(this));
ammAdapter.swap(address(underlyingToken), address(vault), amount, minOut);
sharesReceived = vault.balanceOf(address(this)) - sharesBefore;

require(sharesReceived >= minOut, "ERC4626MarketYieldStrategy: insufficient shares received");
```

The same check can also go in the adapter, measuring `IERC20(tokenOut).balanceOf(msg.sender)` before and after `router.exchange` and requiring the delta to be at least `minAmountOut`. The disposal paths (`_disposeShares`, `_totalWithdraw`, `_skimSurplus`) should measure the underlying-token delta the same way. This also addresses L-12 `6e771a84e82d` (return-value trust). It requires a redeploy as well, so it belongs with (a).

**(d) Make the route test exhaustive.** In `test/unit/CurveAMMAdapter.routeGap.t.sol`, enumerate the `AMMRoutes.json` keys with `vm.parseJsonKeys(json, ".Curve.RouterNG.routes")` instead of two hard-coded keys, so that a newly added route cannot skip validation. This absorbs F-06 `7ef86352a3dd`.
