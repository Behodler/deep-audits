## Finding description and impact

### Summary

`NFTStakerPriceScaledMigrateReady.stake` carries **no `poolState` guard**. A stake performed while the
pool is `Migrating` makes `totalStaked > 0`, which reverts `finalizeAndReset`'s
`require(totalStaked == 0)`. `finalizeAndReset` is the **only** transition back to `Active`, and
`depositFor` requires `Active` — so a single permissionless stake blocks
`InPlaceNFTStakerMigrator.migrateIn` for **every other parked user**, for as long as the staking
continues.

Separately, because `accRewardPerShare` is frozen during `Migrating`, the contract **accepts a stake it
will never pay on**. The staker is neither warned nor refused.

### Vulnerability details

`stake` is gated only on `nonReentrant` and `whenNotPaused`
([`NFTStakerPriceScaledMigrateReady.sol#L617`](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/NFTStakerPriceScaledMigrateReady.sol#L617)):

```solidity
function stake(uint256 amount) external nonReentrant whenNotPaused {
    require(amount > 0, "NFTStaker: zero stake");
    _syncBudget();
    ...
}
```

Compare `depositFor`, which *is* state-gated
([`#L881`](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/NFTStakerPriceScaledMigrateReady.sol#L881)):

```solidity
require(poolState == PoolState.Active, "NFTStaker: not active");
```

and `finalizeAndReset`, the sole route back to `Active`
([`#L925-L929`](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/NFTStakerPriceScaledMigrateReady.sol#L925-L929)):

```solidity
function finalizeAndReset() external onlyOwner {
    require(poolState == PoolState.Migrating, "NFTStaker: not migrating");
    require(totalStaked == 0, "NFTStaker: stake outstanding");
    ...
    poolState = PoolState.Active;
}
```

Accrual is frozen while `Migrating`
([`#L950-L953`](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/NFTStakerPriceScaledMigrateReady.sol#L950-L953)):

```solidity
// While Migrating, emissions are frozen at the `initiateMigration` snapshot
if (poolState == PoolState.Active && block.timestamp > lastRewardTime && totalStaked > 0) { ... }
```

Sequence:

1. Operator calls `initiateMigration`; `poolState` becomes `Migrating`.
2. Any holder of the ERC1155 calls `stake()` — ungated, permissionless, and a legitimate, documented
   user action.
3. `totalStaked > 0`, so `finalizeAndReset` reverts.
4. The pool cannot return to `Active`, so **no** parked user can be migrated in.
5. The user-facing timeout hatch (`claimTimedOut`) lets an impatient parked user re-park, which re-arms
   the timeout clock — so the loop repeats rather than resolving itself.
6. The staker who caused it earns nothing: their position accrues against a frozen
   `accRewardPerShare`, and `pendingReward == 0` is asserted in the PoC.

### Impact

**(1) Availability.** The in-place migration — a core protocol operation — is halted for every other
parked user by a single unprivileged transaction, and can be re-halted indefinitely at the cost of one
stake per cycle.

**(2) Silent user value loss.** The contract accepts a stake that accrues nothing for the duration of
the migration, with no warning and no revert. The affected user loses yield on the staked position for
the whole window.

No assets are at direct risk and no attacker profits — this is pure-cost griefing.

### Honest bounds

- **Likelihood:** medium-to-high, and **more likely accidental than adversarial**. Both the timeout
  hatch and the stake button are legitimate, documented user actions, so an ordinary user can wedge the
  migration without intending to.
- **Assumptions:** the pool is in `Migrating` and at least one ERC1155 unit is outside the migrator's
  custody.
- **External requirements:** none — fully permissionless.
- **Attacker profit:** zero. The griefer forfeits their own accrual for the duration.
- **A sanctioned remedy already exists**, and it is *proven complete by execution*, not by assertion:
  `PoC_Local001::testPauseRemedyIsComplete` shows that `stake`/`unstake`/`claim` are all
  `whenNotPaused`, while every migration primitive and every user escape hatch remains callable while
  paused. So the operator can pause first and migrate safely.
  **This does not make the defect Low:** the pause carries an ecosystem-wide halt cost (filed
  separately this run as CLASS-014, run-20 label L-03 — note this is the *run-20* L-03, not the ledger
  L-03 referenced below), and a remedy that costs a whole-ecosystem outage is not a
  reason to downgrade a defect that a one-line `require` would remove.
- **Severity dispute, disclosed.** The scanner proposed **Low** with a Medium ceiling; classification
  raised it to **Medium** under DECISION-LOG D-10, on the availability leg plus the silent
  zero-accrual acceptance. The dedup record pre-authorised a `medium` ceiling.
- **Three-agent convergence.** Independently surfaced by the code scanner (CODE-003, 2/2 PoC, pause
  remedy verified by execution), the econ scanner (ECON-02, 6-step PoC establishing that the re-park
  re-arms the timeout clock so the loop repeats) and the pattern matcher (PATTERN-003,
  `REWARD-ACCRUAL-ORDER`).

## Recommended mitigation steps

Add the same state gate `depositFor` already carries to `stake`:

```solidity
function stake(uint256 amount) external nonReentrant whenNotPaused {
    require(amount > 0, "NFTStaker: zero stake");
    require(poolState == PoolState.Active, "NFTStaker: not active");   // <-- add
    _syncBudget();
    ...
}
```

This is free, behaviour-preserving during normal operation (the pool is `Active` at all other times),
and it closes both legs at once: the migration can no longer be wedged, and a user can no longer be
silently accepted into a pool that will pay them nothing.

It also removes the need to reach for the ecosystem-wide pause as a migration precondition, which is
the subject of the separate Low filed this run.

Consider applying the same gate to the sibling stakers that share this code shape, so the class does
not reappear on the next clone.
