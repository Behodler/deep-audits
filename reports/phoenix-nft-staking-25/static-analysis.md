### Analyst notes on the ranked delta hits (context only — no triage decision made here)

- **SA-001 / SA-004 (`unused-return` + `calls-loop`, sink 622)** — `configs(_dispatcherIndex)` is re-read **inside** the per-mint loop, so the price is re-quoted every iteration. That is deliberate per the in-code comment (the minter's ramp is authoritative; extrapolating locally would fork the arithmetic). Slither's "unused return" is about the *other* three tuple members, not `price`. The `calls-loop` half is the substantive observation: an unbounded external call per mint, and the loop is the story-029 budget-metered path.
- **SA-002 / SA-013 (`unused-return` / `unchecked-return`, sink 626)** — `nftMinter.mint(...)` returns a value that `batchMint` discards. Worth a look given story-029 reworked exactly this loop, though the minted id is not otherwise consumed.
- **SA-003 (`unused-return`, sink 703)** — `_resolvePaymentPath` reads only `dispatcher` from the same 4-tuple. Same shape as SA-001, different call site.
- **SA-010 (`require-revert-in-loop`, line 621)** — the loop reverts via `BatchMint__PaymentBudgetExhausted(i, price, budget)` when the measured budget cannot cover the next quote. This is the story-029 budget guard itself; the detector is generic advice, but the revert-in-loop is load-bearing here rather than accidental.
- **SA-006 (`calls-loop`, sink 530)** — `INudgeStreamer.pullPendingStream(_nudgeTokens[i])` in a caller-controlled-length loop, in the nudge pre-flush section touched by story-029.
- **SA-014 (`calls-loop`, sink 758)** — `IERC20(rewardToken).balanceOf(address(this))` inside `_snapshotRewards`, the pre-pull snapshot whose ordering relative to the pull the story-029 comments call "load-bearing".
- **SA-017 (`incorrect-equality`, sink 788, pre-existing)** — `amount == 0` strict equality in `_payRewards`. Pre-existing; retained for recall.
