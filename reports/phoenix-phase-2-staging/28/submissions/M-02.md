## Severity

**Medium.**

The blast radius escapes the local chain entirely — it reaches a **published npm artifact consumed outside the repository** — and the drop is silent at every point where it could have been caught: generate, build, and publish. That is availability and function impact on a shipped integration surface, with a stated external requirement (a publish must occur).

Not High: no assets, no attack path, and the failure does surface loudly on the consumer side at their compile time (a missing TypeScript export is a compile error) rather than corrupting behaviour.

Not Low: "it's only the dev stack" stops applying once `npm publish` is in the chain. The npm-publish escape is the load-bearing fact — without it this would be Low.

## Description

`wagmi.config.ts:75` requests a Foundry artifact by path:

```ts
'StableStaker.sol/StableStaker.json'
```

Story 080's retype landed the following at `script/DeployMocks.s.sol:84`:

```solidity
import {StableStakerV1} from "stable-staker/versions/v1/StableStakerV1.sol";
```

and `lib/stable-staker/src/StableStaker.sol` no longer exists. A clean build therefore emits `out/StableStakerV1.sol/StableStakerV1.json` and **never** `out/StableStaker.sol/StableStaker.json`. The configured path resolves to nothing.

**This was masked on the development machine by a stale artifact.** `out/StableStaker.sol/StableStaker.json` was present but dated **2026-06-12** — three months older than the fresh artifacts at `2026-09-07 11:14:53` — with metadata still recording the now-deleted source path. Removing that stale artifact and running the generator for real proved the drop:

```
$ npx wagmi generate
✔ Validating plugins
✔ Resolving contracts          <- green. exit 0. no warning.
✔ Writing to hooks/generated.ts

$ git diff --stat hooks/generated.ts
 hooks/generated.ts | 710 ------------------------------------------

$ grep -c stableStakerAbi hooks/generated.ts
0
```

The wagmi foundry plugin resolves the `artifacts` globs **leniently**: a path that matches nothing produces no export and no diagnostic. Exit code 0. Nothing an operator or a CI gate would catch.

**The amplifier is the publish chain.** `update:hooks` runs the generator, patches the package version, and runs `npm publish`. A clean-checkout CI machine — which by construction has no stale `out/` — therefore publishes a hooks package missing `stableStakerAbi` and reports success.

**Second-order nuance, and the reason the drift went unnoticed for three months:** on a developer machine holding the stale artifact, the emitted ABI happens to be **signature-identical to StableStakerV1 — 63 entries against 63, zero differences**. The local output was correct *by coincidence*, not by construction. There was no observable symptom to prompt investigation.

## Impact

Downstream consumers of the published hooks package lose the StableStaker bindings entirely, with no build-time and no publish-time error. A silent drop is materially worse than a loud failure, because there is no point at which anyone is told: the generator says green, the publish says success, and the first party to learn is a consumer outside this repository whose own build breaks.

No on-chain funds are at risk. The blast radius is a published npm artifact rather than local dev, which is what lifts this above the other `dev`-cluster items in this run.

Likelihood is high and unconditional on the current configuration — no special state is required; the stale artifact was the only thing hiding it.

## Proof of Concept

A Foundry test is the wrong instrument for a build and packaging defect: there is no on-chain state transition to assert, and `forge test` cannot observe artifact-glob resolution inside the wagmi CLI or what reaches `npm publish`. The evidence is the recorded command sequence and its observed output, given verbatim so it is re-runnable.

**Reproduction:**

```bash
# 1. Confirm the masking artifact is stale
ls -l out/StableStaker.sol/StableStaker.json
#   -> mtime 2026-06-12   (fresh artifacts from this build: 2026-09-07 11:14:53)
#      its metadata still records the now-deleted source path

# 2. Remove it — this is the state of any clean checkout / CI machine
rm -rf out/StableStaker.sol

# 3. Run the generator exactly as `update:hooks` does
npx wagmi generate
```

**Observed:**

```
✔ Resolving contracts
(exit 0 — every checkmark green, zero warnings)

$ git diff --stat hooks/generated.ts
 hooks/generated.ts | 710 ------------------------------------------

$ grep -c stableStakerAbi hooks/generated.ts
0
```

Supporting evidence: `wagmi.config.ts:75`; `script/DeployMocks.s.sol:84`; `28/script-audits/dev/side-effects.json` → `clusterInteractions[update:hooks / wagmi generate]`. Last run 2026-09-07 (live command execution).

## Recommended Mitigation

Point the artifact at the type actually deployed: `'StableStakerV1.sol/StableStakerV1.json'` (and export it as `stableStakerV1Abi`, or alias it to keep the consumer-facing name stable).

Independently, close the silent-drop class: wagmi's foundry plugin resolves the `artifacts` globs leniently, so add an explicit post-generate assertion to `update:hooks` — fail the script if any expected export name is absent from `hooks/generated.ts` — so a missing artifact can never reach `npm publish`.

Delete stale `out/` entries in CI (`forge clean` before `wagmi generate`) so local runs and CI agree.
