ANALYSIS (run-03) - THE TRAP REPRODUCED THIS TIME. RUN-02'S VERDICT WAS WRONG.
-----------------------------------------------------------------------
run-02 concluded: "the catastrophic false clean did NOT reproduce in this
version/layout ... --filter-paths matches source_mapping.filename_relative
(which is 'src/Antimatter.sol'), not the absolute path".

That conclusion was an ARTIFACT OF WHERE RUN-02 SCANNED FROM. run-02 ran
Slither out of workspace/antimatter, whose absolute path contains no
'/lib/' component, so the trap condition was never actually present.

run-03 tested both conditions on identical source (hardlinked copies of the
same tree at 3a96fb7), varying ONLY the absolute path:

  abs path WITHOUT '/lib/'  + --filter-paths "lib/"            -> 4 results
  abs path WITHOUT '/lib/'  + --filter-paths "antimatter/lib/" -> 105 results
  abs path WITH    '/lib/'  + --filter-paths "lib/"            -> 0 RESULTS  <-- FALSE CLEAN
  abs path WITH    '/lib/'  + --filter-paths "antimatter/lib/" -> 4 results
  (unfiltered baseline, both trees                             -> 105 results,
   26 contracts, 7 first-party records in default mode)

CONCLUSION: on Slither 0.11.3, --filter-paths "lib/" applied to a tree living
under .../audits/lib/antimatter/ returns ZERO results and exits normally.
Scanning the real submodule path with that filter would produce a totally
silent false clean. The recorded guardrail is CORRECT and must be kept; run-02's
non-reproduction should not be read as retiring it.

SECONDARY POINT, INDEPENDENT OF THE ABSOLUTE PATH:
Even the correctly-anchored filter loses genuine first-party results -
7 first-party records unfiltered vs 4 with "antimatter/lib/". The casualty is
shadowing-local (normalised finding SA-007), whose shadowed element lives in
lib/openzeppelin-contracts; --filter-paths drops any record whose EVIDENCE
touches a filtered file, even when the defect is first-party.

APPROACH ACTUALLY USED IN THE AUTHORITATIVE PASS:
No --filter-paths anywhere. First-party selection is done in post-processing
by testing source_mapping.filename_relative against ^(src/|test/), which is
falsifiable directly from slither-firstparty-all.json.
