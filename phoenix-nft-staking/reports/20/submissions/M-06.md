## Finding description and impact

### Summary

`BatchNFTMinter` derives two different things from the same live external read — the asset it charges callers in, and the §4.1 key it uses to exclude that asset from the nudge payout. Both come from `dispatcher.primeToken()`, resolved at call time from whichever dispatcher `dispatcherIndex` currently points at ([`BatchNFTMinter.sol#L315-L323`](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/BatchNFTMinter.sol#L315-L323)):

```solidity
uint256 _dispatcherIndex = dispatcherIndex;
if (_dispatcherIndex == 0) revert BatchMint__DispatcherNotConfigured();

IERC20 paymentToken;
{
    (address dispatcher,,,) = INFTMinterV2(address(nftMinter)).configs(_dispatcherIndex);
    if (dispatcher == address(0)) revert BatchMint__DispatcherNotConfigured();
    paymentToken = IERC20(ITokenDispatcherV2(dispatcher).primeToken());
}
```

Repointing the dispatcher therefore silently reclassifies balances the contract already holds. story-022 removed the deploy-time *"nudge token == payment token"* assertion and replaced it with a per-call revert, `BatchMint__RewardTokenIsPaymentToken` ([`#L427`](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/BatchNFTMinter.sol#L427)). That revert warns the **caller**. Nothing warns the **operator**, who is the only party in a position to avoid the condition.

### Vulnerability details

The repoint itself is an ordinary, expected maintenance action. It can be performed here via [`setDispatcherIndex` (`#L159`)](https://github.com/Behodler/phoenix-nft-staking/blob/main/src/BatchNFTMinter.sol#L159), and — more importantly — in the **sibling repository** via `NFTMinterV2.replaceDispatcher`, where nothing at all surfaces the coupling. The deploy script's own NatSpec flags `DISPATCHER_INDEX = 4` as *"ASSUMED … the operator MUST confirm"*, i.e. the project itself treats the pin as something that will be revisited.

If the newly-pinned dispatcher's `primeToken()` equals the token that dispatcher donates to the batch minter, two things become true at once:

1. **Availability.** Every legitimate nudge claim that lists the donated token now reverts `BatchMint__RewardTokenIsPaymentToken`, because the §4.1 exclusion and the payment asset are the same address. The nudge mechanism is structurally dead for its intended users.
2. **Value.** The pot the contract has accumulated in that token simultaneously becomes fully sweepable through the post-loop payment-token sweep, i.e. by any `count == 1` caller — the mechanic filed separately this run as **M-01** (`fcaca002…`).

One operator action arms both.

This is not hypothetical. A census of the three real dispatchers in the sibling `yield-claim-nft` repository shows **two of three satisfy the unsafe condition today**:

| Dispatcher | `primeToken()` | Donates to batchMinter | Safe? |
|---|---|---|---|
| `BalancerPoolerV2` (currently pinned) | USDS | USDC | yes |
| `PromotionUniV2_Eth` | USDC (`:189`) | USDC (`:340`) | **no** |
| `NudgeRatchet` | USDC | USDC | **no** |

### Impact

Repointing the pin to either of the two unsafe candidates disables the nudge outright for legitimate users and, in the same action, exposes the accumulated pot to a minimum-cost sweep. The operator receives no signal from either repository that the choice matters.

## Recommended mitigation steps

Restore an **operator-facing** assertion. The per-call revert is a caller-side tripwire and does not serve this purpose.

In the deploy script and in `setDispatcherIndex`, resolve the target dispatcher and compare its prime token against the intended reward asset before the pin takes effect:

```solidity
function setDispatcherIndex(uint256 newIndex) external onlyOwner {
    if (newIndex != 0) {
        (address dispatcher,,,) = INFTMinterV2(address(tokenMinter)).configs(newIndex);
        if (dispatcher == address(0)) revert BatchMint__DispatcherNotConfigured();
        address prime = ITokenDispatcherV2(dispatcher).primeToken();
        // The operator must acknowledge that the new payment asset is not an
        // asset this contract is funded in, or the nudge is dead on arrival.
        if (prime == expectedRewardToken) revert BatchMint__DispatcherPrimeCollidesWithReward(prime);
    }
    dispatcherIndex = newIndex;
}
```

Two supporting steps:

1. Mirror the same assertion in `script/DeployBatchNFTMinter.s.sol` so the condition is caught before deployment, not after.
2. Raise the coupling on the `yield-claim-nft` side, at `NFTMinterV2.replaceDispatcher` — that is where the repoint is actually performed, and it is currently silent.
